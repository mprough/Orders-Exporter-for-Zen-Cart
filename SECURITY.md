# Security

## Supported release

Security fixes are applied to the current 3.x release. Older loose-file releases should be upgraded before reporting a problem.

## Reporting a vulnerability

Do not publish customer information, order exports, credentials, server paths, or an unpatched vulnerability in a public GitHub issue.

Report the problem privately through the [PRO-Webs support desk](https://prowebsinc.zohodesk.com/portal/en/newticket). Include:

- Orders Exporter version.
- Zen Cart and PHP versions.
- A concise description and reproduction steps.
- The security impact.
- Sanitized logs or examples with personal information removed.

## Security design in v3.0.0

- Exports require an authenticated Zen Cart admin session and admin-page permission.
- Files are downloaded directly and are not stored in a public catalog directory.
- Spreadsheet formula prefixes are neutralized.
- Tabs and line endings inside database values are replaced so one value cannot create additional rows or columns.
- Export types are restricted to a fixed allowlist.
- SQL continuation values and batch limits are integers generated by the plugin rather than raw request values.
- The installer makes no changes to order, customer, or product records.

## Handling exported files

Order exports contain personal and business information. Store them only where authorized staff can access them, transfer them through secure channels, and delete them when they are no longer required. Do not place exports in a web-accessible directory.
